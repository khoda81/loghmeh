# Saffron Orbit integration

The welcome screen and app header share the Saffron Orbit study from
`docs/design/motion/studies.html`. The other concepts remain in that gallery.
The illustration is decorative: `ConnectionController` owns the session result.
There is one canvas and no success banner, dismissal timer or animation callback
that controls access to the planner.

| Session phase | Illustration |
| --- | --- |
| Checking | Indeterminate grain orbits; no progress or automatic success |
| Waiting, redirect, login, permission | Grains form an arch, then hold |
| Network, timeout, server, unexpected error | Rice spills without bouncing, then holds |
| Connected | Rice pours into the bowl as it moves into the header and stays there |
| Read-only | Served bowl with the limited-access explanation retained |

The welcome card releases its layout immediately and fades over 220ms. The
calendar appears over 650ms while the same illustration travels into the brand
mark over 1100ms. The scene gradually crops to the bowl and steam, keeping it
legible at header size. The header remains visible while scrolling, and its bowl
follows later connection checks without replaying the entrance. The calendar is
usable as soon as the real model and verified session are available.

The welcome screen's scroll position is reset for the new calendar while the
departing art keeps its visible origin. Focus moves from connection controls
into the calendar. Reconnecting an existing planner keeps its scroll position.
Resolved connection error notices clear after verification; menu and save errors
retain their own lifecycle. Limited access and reconnect failures have compact
explanations beside the calendar.

Pause or reduced motion skips layout travel and reveals the planner immediately.
A result received while paused renders its composed still. Reduced motion has
no rendering loop or dismissal timer. Hidden tabs and offscreen canvases suspend
frames; layout animations finish immediately when paused, hidden or reduced.
Waiting, failure and success entrances stop after settling. Unmount disconnects
observers, listeners, frames and layout animations. Canvas pixel density is
capped at 2.

Verification on 2026-10-29:

- `bun run check`: zero Svelte errors or warnings; TypeScript and manifest
  checks passed.
- `bun test`: 104 tests passed. Ten motion tests cover phase mapping,
  indeterminate checking, terminal settling, pause/resume, visibility, resizing,
  reduced motion, a single entrance, interruption/disposal, scroll anchoring,
  layout release and focus transfer.
- The built preview ran under its existing content security policy, including
  `connect-src 'none'`. Desktop and 390px browser checks covered the welcome
  handoff, pause/resume, limited access and an expired session with an existing
  calendar. The calendar remained present and usable during the handoff.
- At 390px, there was no horizontal page overflow or wrapped brand name, the
  calendar's day headings remained visible, and the bowl aligned with its header
  target after settling. The canvas is hidden from accessibility APIs; text
  announces the actual state and the pause control has an accessible name.
- The local HTTP fixture recorded zero reservation writes throughout these
  browser checks. Separately, the user signed in to university dining in the
  in-app browser. Its reservations page and a selected restaurant's menu loaded
  successfully. No reservation was changed or submitted. That authenticated
  website check does not exercise the extension's full live handshake.
